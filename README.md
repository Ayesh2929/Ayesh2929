## 07 Rendering notes

GitHub sanitizes profile Markdown: it does not run custom JavaScript, WebGL, canvas apps, or embedded iframes inside a README. This document uses a **pre-rendered 3D hero**, a **locally stored looping tesseract animation**, Mermaid diagrams, and a linked STL mesh instead of pretending the README itself is interactive. The repository now also contains a Pages-ready, multi-page companion site with an actual draggable canvas projection.

The animated geometry is a mathematical visualization: a rotating **4D hypercube (tesseract)** is perspective-projected into 3D, then rendered onto a 2D image. The linked STL is a 3D wireframe projection you can open separately in a compatible model viewer.

<details>
<summary><b>Projection recipe</b></summary>

```text
rotate in 4D planes: XY → ZW → XW → YZ
                         ↓
             perspective projection 4D → 3D
                         ↓
             camera projection 3D → 2D
                         ↓
                 looping GIF + STL mesh
```

The artwork and animation are stored in [`assets/`](assets/), so they remain versioned with the profile and do not rely on an external animation host.

</details>

<summary><b>GṛhaLakṣmī · authentication and request boundary</b></summary>

The backend source shows bcryptjs password hashing/comparison, JWT issuance, and authenticated resource routes. The resource handlers scope finance reads and writes to the authenticated `user_id`; family and activity records use the household owner column.

**Deployment caution:** [`auth.js`](https://github.com/Ayesh2929/GrhaLaksmi/blob/main/backend/src/auth.js) currently falls back to a known development JWT secret when `JWT_SECRET` is unset. A real deployment must provide a strong secret through its environment; the diagram describes code flow, not a security certification.

Sources: [`server.js`](https://github.com/Ayesh2929/GrhaLaksmi/blob/main/backend/src/server.js) · [`auth.js`](https://github.com/Ayesh2929/GrhaLaksmi/blob/main/backend/src/auth.js)

```mermaid
sequenceDiagram
    actor Member as Account holder
    participant API as Express REST API
    participant Auth as JWT middleware
    participant DB as PostgreSQL
    Member->>API: POST /api/auth/login
    API->>DB: Find account by email
    DB-->>API: User row + password hash
    API->>API: bcrypt.compare(password, hash)
    API->>API: signToken(user)
    API-->>Member: JWT
    Member->>API: GET /api/expenses + Bearer token
    API->>Auth: authenticate(request)
    Auth-->>API: Verified user identity
    API->>DB: Select rows scoped to user_id
    DB-->>API: User-owned records
    API-->>Member: JSON response
```

</details>

<details>
<summary><b>4D animation · projection math behind the model</b></summary>

A tesseract has 16 vertices and 32 edges. The loop rotates those vertices through four 4D planes, projects the 4D coordinates into 3D, then applies a camera projection to draw the wireframe in 2D.

```text
V = {−1, +1}⁴                 → 16 vertices
edge(u, v) iff one coordinate differs → 32 edges

rotation planes: XY(t) → ZW(0.71t) → XW(0.47t) → YZ(−0.63t)
4D perspective:  scale₄ = 4.25 / (4.25 − w)
3D camera:       scale₃ = 4.1 / (5.3 − z′)
screen:          (cx + x′·scale₃·67, cy + y′·scale₃·67)
```

The animated GIF contains 40 frames. The companion STL stores the same kind of 3D projection as a wireframe mesh with cylindrical edges and vertex nodes. [Open the STL model](assets/tesseract-projection.stl).

</details>
